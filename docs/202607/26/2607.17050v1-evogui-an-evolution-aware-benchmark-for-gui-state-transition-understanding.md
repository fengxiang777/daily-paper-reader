## 摘要
GUI 智能体必须推理动作如何改变界面状态，但端到端成功率将这种能力与感知、接地、规划和恢复混杂在一起。我们引入了 EvoGUI，一个将规范化 GUI 轨迹转换为三种互补的视觉问答探针的诊断框架：时序排序、反向动作/价值预测以及对比式单步后继判别。它们的标签源自轨迹顺序和记录的动作，在轨迹规范化后无需额外的任务标签标注。我们从 Mind2Web 和 WebLINX 实例化了 EvoGUI-Bench，在 120 个领域中产生了 3000 个实例，并对 28 种视觉-语言模型配置进行了零样本评估。最强模型仅达到 60.4 的 EvoGain，而模型规模和 GUI 专业化并不能可靠地预测性能。这些结果将 EvoGUI-Bench 确立为端到端 GUI 智能体评估的可扩展诊断补充，同时暴露了状态转换理解方面的巨大提升空间。源代码公开于 https://github.com/Yyhhh6/EvoGUI。

## Abstract
GUI agents must reason about how actions transform interface states, but end-to-end success rates entangle this ability with perception, grounding, planning, and recovery. We introduce EvoGUI, a diagnostic framework that converts normalized GUI trajectories into three complementary visual question answering probes: temporal ordering, inverse action/value prediction, and contrastive one-step successor discrimination. Their labels are derived from trajectory order and logged actions, requiring no additional task-label annotation after trajectory normalization. We instantiate EvoGUI-Bench from Mind2Web and WebLINX, yielding 3,000 instances across 120 domains, and evaluate 28 vision-language model configurations zero-shot. The strongest model reaches only 60.4 EvoGain, while model scale and GUI specialization do not reliably predict performance. These results establish EvoGUI-Bench as a scalable diagnostic complement to end-to-end GUI-agent evaluation while exposing substantial headroom in state-transition understanding. The source code is publicly available at https://github.com/Yyhhh6/EvoGUI.

## 1. 核心问题与整体含义（研究动机和背景）
*   **核心问题**：现有的 GUI 智能体评测基准通常采用端到端任务成功率，这种指标将**状态转换理解能力**与感知、元素接地、规划、工具使用及错误恢复等多种能力混淆在一起，无法单独诊断智能体对界面状态演化的理解程度。
*   **研究动机**：GUI 交互本质上是“演化感知”的——智能体不仅要看清当前屏幕，还必须理解点击、键入等动作如何改变界面状态。因此，亟需一种**可扩展的、能将状态转换理解能力从端到端成功中解耦出来**的诊断性评测框架。
*   **整体含义**：该工作提出 EvoGUI，旨在将已有的 GUI 操作轨迹自动转化为诊断性的视觉问答题，以补充端到端评测，揭示并量化当前视觉-语言模型在状态转换理解上的真正短板。

## 2. 论文提出的方法论
### 2.1 核心思想
将标准化的 GUI 操作轨迹 `τ = [(s_t, a_t, v_t, s_{t+1}, m_t)]` 自动转化为三种互补的视觉问答（VQA）探针，**完全利用轨迹固有的顺序、动作记录和截图**生成标签，全程无需额外的人工任务标注。

### 2.2 三大诊断探针（VQA Tasks）
*   **T1 时间顺序（Temporal Ordering）**  
    给定同一轨迹中 K ∈ {3,4,5} 张打乱顺序的截图，要求模型恢复其原本的时间先后顺序。评估指标为精确排序准确率。
*   **T2 反向动作/价值预测（Inverse Action/Value Prediction）**  
    给定相邻截图对 `(s_t, s_{t+1})`，要求模型预测导致该状态变化的动作类别（`CLICK`, `TYPE`, `SELECT`）。对 `TYPE` 和 `SELECT` 动作还要求预测精确的键入内容或选择项。报告动作准确率（action-only）和联合动作-价值准确率（joint）。
*   **T3 对比式单步后继判别（Contrastive One-step Successor Discrimination）**  
    给定源截图 `s_t` 和两个混淆的候选下一张截图（`s_{t+1}` 和一个干扰项），要求模型选出**真实记录的即时后继**。干扰项分三级：跨轨迹、同域、同轨迹长间隔（`s_{t+n}, n≥3`）。评估指标为成对准确率，**长间隔干扰项**能更灵敏地检验模型是否在判定“记录的单步转换”而非仅“工作流大致可达”。

### 2.3 自动构建流程
1.  **轨迹规范化**：将 Mind2Web、WebLINX 等来源中的操作映射至统一动作词汇（`CLICK`, `TYPE`, `SELECT`），形成标准五元组轨迹。
2.  **任务自动发掘**：基于时序、动作记录、截图对自动抽取上述三个任务的实例。
3.  **人工质量控制**：仅对 T3 实例进行目视检查，剔除那些视觉差异无法合理解释为记录动作所致的模糊项（如页面加载、异步更新），但**不更改任务标签**，保留机械生成的轨迹相邻关系作为正确目标。

### 2.4 综合评价指标 EvoGain
为将三个随机基线不同的任务得分综合为单一可比数值，提出 **EvoGain 指数**：  
`NormScore_i = (ModelScore_i - Baseline_i) / (100 - Baseline_i) × 100`  
`EvoGain = macro-average(NormScore_T1, NormScore_T2_joint, NormScore_T3)`  
该指标衡量模型在消除随机猜测后的相对提升程度。

1.  **巨大的提升空间**：当前最强模型（Gemini-3-Flash-Preview）的 EvoGain 仅 **60.4**，远未饱和，尤其在 T1（时间顺序）上准确率仅 58.3%。

## 7. 优点
*   **自动化与可扩展性强**：核心创新在于从轨迹内部**自动抽取诊断标签**，极大降低了扩展到新数据集或新环境的成本。
*   **诊断细粒度**：三个任务从时间结构、因果归因、可达性判别等不同侧面解耦状态转换理解，避免了端到端得分的笼统性。
*   **指标设计合理**：EvoGain 能够消除随机基线差异，使不同任务得分可综合比较；Bootstrap 置信区间提高了排名的统计严谨性。
*   **控制实验完善**：通过黑图像、消融指标、分辨率 Sweep 等多重控制，有力支撑了核心结论，包括排名的稳健性和视觉证据的不可或缺。
*   **实践指导意义**：明确提出“演化感知能力应直接评测”，指出了一个当前研究可能被忽视的薄弱环节。

## 8. 不足与局限
*   **领域与操作类型局限**：当前基准实例主要来自 **Web 浏览器交互**，动作词汇仅限于 `CLICK`, `TYPE`, `SELECT`。虽在架构上可扩展至移动端（如 SWIPE, LONG-PRESS）和桌面端，但此拓展尚未验证。
*   **T2 价值预测并非纯因果推理**：T2 的联合准确率强依赖 OCR 和文本绑定能力，因此该探针的诊断结果混合了**状态理解与文字感知**。
*   **T3 局限性**：干扰项是**采样**得到的，而非通过执行验证的“不可达”状态；模型答对仅表示可以辨别采样出的干扰项，不能证明其能判定某个屏幕在所有可能的系统状态下都绝对不可达。
*   **外部效度待加强**：与 OSWorld 成功率的关联分析样本量小（n=5）且报告方式存在部分混杂，目前仅能视为鼓励性的初步关联，**尚不能宣称 EvoGain 可以预测实际应用中的代理成功**。
*   **人工质检局限性**：虽声称无需任务标注，但 T3 最终仍依赖人工检查进行质量控制，大规模的自动化质量保证仍是挑战。
