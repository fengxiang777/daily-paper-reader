## 摘要
我们介绍了ARBIGRAPH，一个用于评估工具辅助语言智能体是否能够在扩展的推理工作流程中保留、更新、组合和丢弃任务相关上下文的基准生成器。ARBIGRAPH将每个任务表示为一个带有可执行Python求解器的自然语言问题，并通过类型化的中间状态（此处实例化为标量和列表值）组合任务。这种设计允许生成具有可控性的任务图，其长度、依赖结构、干扰项数量和值类型均可变化，同时保持精确的自动验证。我们使用数学、GSM风格文字题和Python追踪等任务类别实例化了ARBIGRAPH，并在四种拓扑结构下评估了一个Qwen3.5-27B工具辅助智能体。结果显示在孤立任务上具有高准确率，但在更复杂的依赖任务上出现显著下降：在依赖数学任务的分支链上，准确率最多下降33.3%。这表明ARBIGRAPH暴露了仅靠单任务评估无法发现的失败。我们的代码、生成的数据集和评估结果可在https://github.com/pavelgolikov/ArbiGraph.git获得。

## Abstract
We introduce ARBIGRAPH, a benchmark generator for evaluating whether tool-assisted language agents can retain, update, compose, and discard task-relevant context across extended reasoning workflows. ARBIGRAPH represents each task as a natural-language problem with an executable Python solver, and composes tasks through typed intermediate states, instantiated here as scalar and list values. This design enables controllable task graphs whose length, dependency structure, distractor count, and value type can be varied while preserving exact automatic verification. We instantiate ARBIGRAPH with math, GSM-style word-problems, and Python-tracing task categories, and evaluate a Qwen3.5-27B tool-assisted agent across four topologies. The results show high accuracy on isolated tasks but substantial degradation on more complex dependent tasks: accuracy drops by up to 33.3% on branching chains of dependent math tasks. This shows that ARBIGRAPH exposes failures that are not visible from single-task evaluation alone. Our code, generated datasets, and evaluation results are available at https://github.com/pavelgolikov/ArbiGraph.git

- **研究动机**：随着智能体处理的工作流越来越长且相互交织，上下文管理的缺陷已成为主要瓶颈，而当前基准要么仅测试长文档检索，要么只固定一种组合模式，无法系统、可控地测量上下文压力。
- **整体含义**：提出 ARBIGRAPH，一个可生成**任意可扩展、可验证任务图**的基准，将上下文视为类型化计算状态，通过改变图的长度、依赖结构、干扰项数量和值类型，独立地评估智能体的上下文管理能力。

### 2. 论文提出的方法论
- **核心思想**：将每个子任务建模为自然语言问题+可执行 Python 求解器，通过**类型化中间状态**（标量或列表）进行组合，生成带依赖的任务图，用户可自定义图的拓扑（DAG）。

  - **任务节点**：每个节点包含输入 `xi`、预处理器 `ai`、提示生成器 `pi`、后处理器 `bi`、输出 `yi` 和求解器 `si`。求解器仅用于生成真值，对智能体不可见。
  - **类型契约与组合**：任务通过输入/输出类型（标量/列表）进行匹配，边 `Ti → Tj` 仅在输出类型与输入类型兼容时有效。依赖关系被显式命名并呈现给智能体，但不透露答案。
  - **适配器**：预处理/后处理适配器用于在全局数据类型（标量/列表）与任务特定参数之间转换，并能控制中间任务复杂度（如限制列表长度、数值大小）。

    3. **GSM 风格任务**：标量到标量的自然语言算术文字题，源自 GSM-Symbolic，用于增加语言多样性。
- **上下文管理的测量**：定义四种拓扑结构（图 2）：
  - **基线**：单任务。

### 6. 论文的主要结论与发现
- 基线准确率很高（数学 94.5%，Python 96.8%，GSM 100%），说明目标任务本身对模型而言是可求解的。
- **遗忘拓扑**下准确率下降较小但可观测（数学降至 89.2%，Python 92.5%），证明无关干扰也会带来干扰。
- **链和多链拓扑**导致显著性能退化：数学链准确率降至 75.5%，多链进一步降至 61.2%（**下降 33.3%**）；Python 追踪相对稳健（链 90.1%，多链 90.5%）；GSM 保持 96.0% 链准确率。
- **过程指标**显示，复杂拓扑使平均生成 token 数和交互回合数大幅增加，尤其在数学链和多链上。
- 结论：ARBIGRAPH 成功暴露了**单任务评估无法发现的上下文管理故障**，且不同任务类型对上下文压力敏感度不同。

### 7. 优点
- **灵活可扩展**：图拓扑、任务数量、干扰项、依赖模式均可自定义，无需手工编写每一个长链实例。
- **精确验证**：所有输出都有可执行求解器生成的精确真值，消除评分主观性。
- **诊断性强**：通过对比四种拓扑，能分离局部求解能力与状态传播/遗忘/干扰导致的失败。
- **开源可复现**：提供代码、生成数据集和完整评估结果，便于社区扩展和复现。
- **类型契约与适配器设计**：将任务间通信标准化，并控制中间输出复杂度，防止爆炸。

### 8. 不足与局限
- **模型覆盖单一**：仅评估了 Qwen3.5-27B 一个模型，缺少与其他模型族（如 GPT‑4、Claude 3.5 等）的对比，结论的泛化性受限。
- **任务范畴较窄**：当前仅支持标量/列表值，无法处理图像、视频或结构更复杂的状态；任务类别也只有数学、代码追踪和简单算术文字题。
- **拓扑相对基础**：评估只在 1、4、8 个节点构成的特定拓扑上进行，未涉及大规模图（如几十个节点）或循环、动态拓扑等真实世界复杂场景。
- **工具使用简单**：智能体仅配备计算器，未涉及文件系统、浏览器等外部工具，限制了与实际智能体工作流的对应。
- **偏差风险**：任务模板、适配器阈值和随机种子固定，可能存在对特定模板的过拟合；且仅关注最终任务准确率，未深入分析中间状态错误传播的细粒度模式。
- **应用限制**：目前仅作为诊断基准，难以直接迁移至评估生产环境中的上下文管理。
