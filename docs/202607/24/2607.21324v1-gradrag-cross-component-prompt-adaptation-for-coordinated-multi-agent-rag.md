## 摘要
检索增强生成（RAG）系统越来越多地使用多个LLM智能体。然而，大多数先前的工作都是孤立地优化组件，而不是在整个流水线中协调改进。我们引入了GRADRAG，这是一个跨组件提示自适应的框架，它将RAG流水线建模为计算图，并传播结构化的评估反馈来更新上游智能体。评估器对下游答案和支持证据进行评判，产生可操作的反馈，提示优化器使用这些反馈迭代地更新自适应智能体，例如检索器、图构建器和回答器。当输出被认为令人满意时，评估器还会触发提前停止。我们在SQUALITY和QMSUM基准上评估了GRADRAG，涵盖两种检索范式：使用IRCoT风格查询细化的扁平块检索（Trivedi等人，2023年），以及从文档中构建并迭代丰富实体关系图的图检索。在两种设置下，GRADRAG都一致地优于仅更新最终生成器的单步细化基线，在LLM评判的成对比较中实现了12-15个百分点的净偏好优势，且大多数收益在两次细化迭代内实现。

## Abstract
Retrieval-Augmented Generation (RAG) systems increasingly employ multiple LLM agents. Yet, most prior work optimizes components in isolation rather than coordinating improvements across the pipeline. We introduce GRADRAG, a framework for cross-component prompt adaptation that models the RAG pipeline as a computational graph and propagates structured evaluation feedback to update upstream agents. An Evaluator critiques downstream answers and supporting evidence, producing actionable feedback that a Prompt Optimizer uses to iteratively update adaptive agents, such as retrievers, graph constructors, and answerers. The Evaluator also triggers early stopping when the output is deemed satisfactory. We evaluate GRADRAG on the SQUALITY and QMSUM benchmarks under two retrieval paradigms: flat chunk-based retrieval using IRCoT-style query refinement (Trivedi et al., 2023), and graph-based retrieval that constructs and iteratively enriches an entity-relation graph from the document. Across both settings, GRADRAG consistently outperforms one-step refinement baselines that update only the final generator, achieving a 12-15 percentage point net preference margin in LLM-judged pairwise comparisons, with most gains realized within two refinement iterations.

### 1. 论文的核心问题与整体含义
- **核心问题**：当前多智能体 RAG 系统中，各组件（检索、证据构建、答案生成）通常被独立优化，下游输出的评估信号很少用于改进上游组件。这种“孤岛式”优化导致早期错误（如检索不全或证据组织不当）向下传播，限制最终性能。
- **整体含义**：论文提出 **GRADRAG**（Gradient-based RAG），旨在将 RAG 流水线视为一个整体计算图，通过**跨组件提示自适应**（Cross-Component Prompt Adaptation）让下游评估反馈能够直接更新多个上游智能体的提示，实现端到端的协调优化，从而提升多智能体 RAG 的推理质量。

### 2. 方法论
- **核心思想**：将 RAG 流水线建模为计算图，节点为各种智能体（检索器、图构造器、答案生成器）。在测试时迭代执行：前向传播产生答案 → Evaluator 评判答案与证据 → Prompt Optimizer 将反馈转化为上游智能体的提示更新 → 进入下一次迭代。
- **关键技术细节**：
  - **计算图与自适应智能体**：图中包含固定智能体（如经典检索器）和自适应智能体（其提示可被更新）。自适应智能体包括 Retrieval Agent、Graph Extraction Agent、Answer Generation Agent 等。
  - **评估与反馈**：Evaluator 分析生成的答案和支持证据，判断是否“满意”（SATISFACTORY），若否则输出结构化自然语言反馈，指出缺失信息、弱推理链或无关上下文。
  - **提示自适应**：Prompt Optimizer 将反馈转化为针对每个自适应智能体的具体提示修改，例如指导检索器生成更聚焦的子查询，或指导图提取器关注缺失的实体关系类型。
  - **早停机制**：当 Evaluator 判定答案满意时停止迭代，或达到最大迭代次数（实验中设为 3）时终止。
  - **算法流程**（对应 Algorithm 1）：
    1. 输入：查询 \(q\)，文档 \(D\)，初始提示集 \(\{p_a\}\)，最大迭代 \(T\)
    2. 循环 \(t=1\) 到 \(T\)：
        - 执行前向传播，生成证据和答案 \(y_t\)
        - Evaluator 评判 \((y_t, \text{证据})\)，给出反馈 \(f_t\) 和决定 \(d_t\)
        - 若 \(d_t=\text{SATISFACTORY}\)，返回 \(y_t\)
        - 否则，对每个自适应智能体 \(a\)，更新提示 \(p_a \leftarrow \text{Optimize}(p_a, f_t)\)
    3. 返回最终答案 \(y_T\)
  - **两种实例化管线**：
    - **向量 RAG（Flat Retrieval）**：基于 IRCoT 策略，Retrieval Agent 迭代生成子查询，混合稠密与稀疏检索。反馈可同时更新 Retrieval Agent 和 Answer Generation Agent。
    - **图 RAG（Graph-based Retrieval）**：Graph Extraction Agent 构建实体关系图，社区检测后生成摘要和候选答案。反馈可更新 Graph Extraction Agent（如增加缺失实体/关系类型）和 Answer Generation Agent。

### 6. 论文的主要结论与发现
- GRADRAG 在两种检索范式下均**一致优于**仅更新答案生成器的单步细化基线，LLM Judge 评比的**净偏好优势为 12～15 个百分点**（胜率约 55%～57%）。

- 跨组件提示自适应使得输出在信息密度和主题聚焦度上逐步改善，而非单纯增加长度。
- 该框架验证了将下游评判信号传播到上游组件是提升多智能体 RAG 管线整体性能的有效策略，且方法通用，适用于扁平检索和图检索两种架构。

### 7. 优点
- **新颖的协调机制**：首次在多智能体 RAG 中系统性地用下游评估反馈同时驱动多个上游组件（检索、图构建）的提示更新，超越了现有单步答案改写范式。
- **框架通用性**：基于计算图的抽象，能统一适配扁平向量检索和图检索，可扩展到其他管线性组件。
- **实验设计严谨**：通过受控消融（单步 vs. 跨组件）精确量化协调收益；引入位置一致性检查和人工评估，增强了 LLM Judge 结果的可靠性。
- **效率与解释性**：无需重新训练模型，纯测试时优化；并提供响应动态分析，揭示改进来源于信息密度和聚焦度提升。

### 8. 不足与局限
- **计算开销**：每查询需多次迭代和 LLM 调用，平均耗时增加约 10%，token 消耗上升，对大规模部署或低延迟场景不友好。
- **逐实例优化范式**：当前每个查询独立优化，优化后的提示不跨实例复用，导致效率偏低，不能像 DSPy 等框架一样积累全局最优提示。
- **评估器局限性**：Evaluator 仅依赖内部知识（无参考答案），可能引入一定的评估偏差；未与外部奖励模型或准确率指标结合。
- **数据集覆盖**：仅在两个英文长文档 QFS 数据集上测试，未在更多领域或简短问答任务中验证；任务限于文档内检索，不涉及开放域多文档场景。
- **泛化性风险**：依赖特定 LLM（Gemini 系列）和评价模型，不同模型家族下的表现有待检验；无模型微调，完全依赖提示工程，在极端复杂推理上的提升空间未知。
