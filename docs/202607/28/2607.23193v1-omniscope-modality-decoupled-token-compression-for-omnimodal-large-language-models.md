## 摘要
现有面向全模态大语言模型的令牌压缩方法通常依赖一种模态来决定在另一种模态中保留哪些内容。我们表明这一假设往往不成立：对于同一查询，音频和视频的相关性往往在不同时刻达到峰值。这种跨模态显著性不匹配使得单向引导在激进压缩下容易丢弃对答案至关重要的线索。我们提出OmniScope，一种无需训练的令牌压缩框架，该框架以查询作为共享语义锚点，同时分别估计音频和视频的相关性。OmniScope分配模态特定的令牌预算，使用锚点-增量策略修剪视觉令牌，同时保留全局上下文和时序变化，并在每秒内合并音频令牌，以在保持时序连续性的同时减少冗余。在四个音视频基准以及两个Qwen2.5-Omni模型规模上，OmniScope在所有压缩设置下均取得了最佳平均准确率。在总体令牌保留率25%时，它实现了高达3.53倍的预填充加速和超过15%的GPU内存减少，而平均准确率仅下降0.35点。这些结果揭示了全模态大语言模型推理的一个简单设计原则：跨模态共享查询，但不共享显著性估计。代码可在https://github.com/MAC-AutoML/OmniScope获取。

## Abstract
Existing token compression methods for omnimodal large language models typically rely on one modality to determine what to retain in the other. We show that this assumption often breaks down: for the same query, audio and video relevance often peaks at different moments. This cross-modal salience mismatch makes unidirectional guidance prone to discarding answer-critical cues under aggressive compression. We propose OmniScope, a training-free token compression framework that uses the query as a shared semantic anchor while estimating relevance separately for audio and video. OmniScope allocates modality-specific token budgets, prunes visual tokens with an anchor-delta strategy that preserves both global context and temporal changes, and merges audio tokens within each second to reduce redundancy while maintaining temporal continuity. Across four audio-video benchmarks and two Qwen2.5-Omni model scales, OmniScope achieves the best average accuracy across all compression settings. At 25% overall token retention, it delivers up to 3.53x prefill speedup and more than 15% GPU memory reduction, with only a 0.35-point drop in average accuracy. These results suggest a simple design principle for OmniLLM inference: share the query across modalities, but not the salience estimates. The code is available at https://github.com/MAC-AutoML/OmniScope.

## 1. 核心问题与研究动机
全模态大语言模型（OmniLLMs）能联合处理视频、音频与文本，但推理时视听令牌数量随视频时长快速增长，带来严峻的计算与内存压力。现有面向全模态的令牌压缩方法（如 OmniZip）通常采用**单向跨模态引导**，即用一种模态的显著性指导另一模态的保留策略。

本研究发现这一假定并不可靠：**同一查询下，音频与视频的关键片段往往出现在不同时刻**，这种跨模态显著性错配（cross‑modal salience mismatch）在激进压缩时会导致关键信息被错误丢弃。针对这一问题，OmniScope 提出了一种**模态解耦、查询感知、无需训练的令牌压缩框架**，为高效全模态推理确立“共享查询，但独立估计显著性”的设计原则。

## 2. 方法论
OmniScope 分为三个阶段，所有步骤均不依赖额外训练。

- **查询感知评分与预算分配**  
  - **视觉评分**：使用外部 CLIP 模型，对视频每一帧与查询文本计算余弦相似度，得到帧级重要性 \( s_v^{(t)} \)。  
  - **音频评分**：利用 OmniLLM 自身的音频编码器输出与查询词嵌入计算门控跨模态相似度，并聚合为逐秒重要性 \( s_a^{(s)} \)；对高分秒点周围应用衰减传播以保留上下文。  
  - **模态独立预算**：根据全局保留比，按位置重要性比例将令牌预算分配给各帧/秒，视频和音频的压缩比独立配置。

- **视觉压缩：锚点‑增量时空压缩**  
  交替指派帧角色：  
  - **锚点帧（偶数索引）**：基于密度聚类保留空间上最具区分性的令牌，覆盖全局语义。  
  - **增量帧（奇数索引）**：根据预算丰富度自适应切换策略。预算充足时，使用空间‑时间不可替代性乘积筛选既空间冗余又时间冗余的令牌；预算紧张时，仅保留与前帧余弦相似度最低的令牌，集中捕获最显著的时序变化。

- **音频压缩：每秒二分软匹配合并**  
  在每一秒内，将音频令牌分为偶索引（源）和奇索引（目标）两组，计算相似度矩阵，将最相似的源‑目标对进行平均融合，减少令牌数量同时保持时序连续性和信息完整性。

## 6. 主要结论与发现
- OmniScope 在所有压缩比和模型规模下取得**最高平均准确率**，45% 令牌保留时几乎无损。  
- 在 25% 令牌保留的激进设置下，**预填充速度提升 3.53 倍，GPU 内存节省 >15%，平均精度仅降 0.35 点**（7B 模型），显著优于 OmniZip（下降 1.55 点）。  
- 模态解耦压缩策略使模型在高压缩比下仍保持鲁棒，避免了单向跨模态引导导致的错误丢弃。  
- 压缩可增强跨窗口注意力交互，但只有保留本模态的查询相关令牌，才能将增强的注意力导向任务关键线索。

## 7. 方法亮点
- **原则鲜明**：首次明确指出和量化跨模态显著性错配问题，并据以设计解耦框架。  
- **无训练、即插即用**：无需微调，具有强通用性。  
- **视觉 AD‑STC**：通过锚点‑增量交替，巧妙平衡空间覆盖与时间增量，且能按预算自适应切换策略。  
- **音频微秒级合并**：利用二分软匹配在保持时序连续性的前提下融合冗余，优于直接丢弃或池化。  
- **查询感知评分独立于模型推理**：音频评分复用模型内部嵌入，零额外内存开销；视觉评分虽有固定开销，但在长生成场景被摊薄。

## 8. 不足与局限
- **外部视觉评分器依赖**：使用 CLIP 引入不可忽略的一次性开销，虽可摊薄但并非完全零成本，且若 CLIP 与 OmniLLM 视觉编码器对齐不佳，可能带来偏差。  
- **模型范围局限**：仅在 Qwen2.5‑Omni 上测试，未探索对其他全模态架构（如 VITA、Gemini）的泛化性。  
- **推理延迟对比**：尽管预填充加速显著，但因 CLIP 开销，端到端延迟在极短生成场景下可能不占优。  
- **未考虑更复杂任务**：评估集中在选择题形式的视频问答，尚未在开放式生成、多轮交互等场景中验证。  
- **压缩比设定需人工指定**：视频和音频压缩比为固定值，未提供自动调优机制。  
- **可能与量化、剪枝等正交技术结合效果未知**。
