## 摘要
现有的大型语言模型评估覆盖了知识、推理、编码和工具使用，但它们很少将受约束工作流中生成的可验证交付物作为评估单元。我们引入了SQBench，这是一个用于评估语言模型代理在面向生产的任务交付的基准。SQBench v1.0包含220个标准化任务，组织为L1原子能力、L2组合技能和L3业务场景。每个任务要求代理处理输入资产，使用可用工具，并产生明确指定的交付物。评估首先计算功能性完成度，然后从10维风险矩阵中独立证据触发的因素推导出风险惩罚和性能。严格通过要求完成度=1且风险惩罚=0。我们在一个通用协议下评估了27种模型配置，每个配置-任务对运行一次。最高预定义的加权通过率@1为60.5%。在L3上的平均严格通过率@1为18.5%，并且每个配置在L3上的表现都比在L1和L2上差，表明在领域约束下的交付是当前任务集中的一个共同弱点。在2348个完成度=1的结果中，有113个（4.8%）因不可验证的引用、不适当的资源使用或格式违规等风险而未能通过严格标准。这些结果表明，仅功能性完成不能完全表征交付质量，风险判定应单独报告。

## Abstract
Existing evaluations of large language models cover knowledge, reasoning, coding, and tool use, but they rarely treat a verifiable deliverable produced within a constrained workflow as the unit of evaluation. We introduce SQBench, a benchmark for evaluating production-oriented task delivery by language-model agents. SQBench v1.0 contains 220 standardized tasks organized into L1 atomic capabilities, L2 composite skills, and L3 business scenarios. Each task requires an agent to process input assets, use available tools, and produce an explicitly specified deliverable. The evaluation first computes functional Completion and then derives Risk Penalty and Performance from independently evidenced triggers in a 10D Risk Matrix. A Strict Pass requires Completion = 1 and Risk Penalty = 0. We evaluate 27 model configurations under a common protocol, with one run per configuration-task pair. The highest prespecified Weighted Pass@1 is 60.5%. Mean Strict Pass@1 on L3 is 18.5%, and every configuration performs worse on L3 than on both L1 and L2, indicating that delivery under domain constraints is a shared weakness within the current task set. Of 2,348 results with Completion = 1, 113 (4.8%) fail the Strict Pass criterion because of risks such as unverifiable citations, inappropriate resource use, or format violations. These results show that functional completion alone does not fully characterize delivery quality and that risk determinations should be reported separately.

    *   SQBench 旨在系统地量化和诊断 AI 代理在“制造可用成果”而非仅仅是“回答正确问题”方面的能力与风险。

### 2. 方法论

*   **核心思想**：
    *   将工作模式抽象为版本化的、包含初始资产、明确约束和可评分交付物的**任务实例**。
    *   评估不只看“是否完成”（`Completion`），更要看交付过程是否引入了**风险**（`Risk Penalty`），并以此定义**严格通过（`Strict Pass`）** 标准。

*   **关键技术细节**：
    *   **三层任务体系**：
        1.  **L1（原子能力）**： 100个任务，诊断基础执行能力（如指令遵循、长上下文处理、边界处理）。
        2.  **L2（组合技能）**： 60个任务，评估将多种能力组合成工作流的能力（如办公协作、数据分析、深度研究）。
        3.  **L3（业务场景）**： 60个任务，在特定行业（金融、工业、医疗、公共管理）约束下交付可审计成果的能力。
    *   **10D风险矩阵**： 定义了10个维度的风险，用于评估交付物在可信度、合规性和可审计性上的缺陷。风险触发需基于交付物或执行轨迹中的**独立证据**。部分维度示例如下：
        *   **D1（事实与出处幻觉）**： 信息缺乏事实依据或来源支持。
        *   **D2（格式与指令违规）**： 违反明确的格式、路径、字段要求。
        *   **D3（合规与安全越权）**： 代理超出授权、侵犯隐私。
        *   **D4（低效与资源滥用）**： 明显的低效循环、资源限制违规。
        *   **D5**： 工具状态幻觉或忽略工具错误。
        *   **D6**： 过早终止或遗忘目标。
    *   **核心公式与流程**：
        1.  **功能完成度 (`Completion`)**： 通过自动化检查（结构化输出、代码执行）和 LLM 裁判打分（语义、报告质量），按预定义权重加权求和得到，范围 [0, 1]。
        2.  **风险惩罚 (`Risk Penalty`)**： 对触发的风险维度，按预定义惩罚值（正数）求和。
        3.  **交付性能 (`Performance`)**： `max(0, Completion - Risk Penalty)`，一个连续诊断分数。
        4.  **严格通过 (`Strict Pass`)**： 一个二元决策，等价于 `Completion == 1` 且 `Risk Penalty == 0`。
        *   **核心评估指标**： 加权严格通过率@1 (`Weighted Pass@1 = 0.2 * L1_Pass@1 + 0.6 * L2_Pass@1 + 0.2 * L3_Pass@1`)。

### 3. 实验设计

*   **数据集 / 场景**：
    *   **自身 SQBench v1.0 基准**： 包含 220 个任务（L1: 100, L2: 60, L3: 60）。L3 覆盖金融、工业、医疗、公共管理四个行业，每个行业 15 个任务。
    *   **执行环境**： 任务在受控的、隔离的工作区中运行。网络权限视任务而定（196 个禁网，24 个联网）。
    *   **评分模式**： 113 个任务为全自动评分，107 个任务结合了自动评分和 LLM 裁判。

*   **对比方法 / 模型配置**：
    *   评估了 **27 种不同的模型配置**。配置的定义包括基础模型及其调用参数（如不同的推理努力程度 `High`, `Max`），被视为独立参评项。

### 6. 主要结论与发现

*   **最高分有限，L3层是共同弱点**： 表现最好的模型配置（Kimi K3）加权严格通过率仅为 **60.5%**。所有27个模型在**L3场景下的平均严格通过率仅为18.5%**，且每个模型在L3的表现均差于L1和L2，表明在领域约束下交付是当前模型的普遍短板。
*   **功能完成不等于成功交付**： 在所有功能完成（`Completion=1`）的 2,348 次运行中，有 **113次（4.8%）因触发风险而未能严格通过**，尤其是在L2层（占L2完成的10%）。这表明仅报告功能完成度会遗漏交付质量的关键信息。
*   **主要风险来源**： 在“完成但未通过”的案例中，最常见的风险触发因素是：
    *   `D4`（低效与资源滥用）： 触发 92 次。
    *   `D1`（事实与出处幻觉）： 触发 5 次。
    *   `D2`（格式与指令违规）： 触发 6 次。
*   **行业与任务类型差异**： 在L3中，定量审计任务（10.7%）的通过率低于复杂业务（20.2%）和合规风控（24.6%）任务。

### 7. 优点

*   **评估单元创新**： 将评估重点从“答案的正确性”创新性地转移到“**交付物在约束下的可用性、合规性与风险**”，更贴近真实业务场景。
*   **多维度的细粒度评估**： 评价体系不仅给出总分，还通过**三层任务体系、行业细分、10D风险矩阵**对代理的能力和交付风险进行了结构化诊断，其结果（如 Completion vs. Strict Pass 的差异）具有很强的可解释性和审计价值。
*   **实验设计严谨**： 对任务版本化、执行环境隔离、评分规则统一且预定义，确保了内部可比性和公平性。向评估流程中引入“风险证据链”的概念，使得判定不再是黑箱。

### 8. 不足与局限

*   **覆盖范围受限**： 220个任务和4个行业的规模相对有限，是“工作模式的抽象”，不能声称代表所有生产环境或职业。
*   **统计稳健性不足**： 每个模型-任务对仅运行一次（Pass@1），无法计算置信区间，难以对排名接近的模型得出统计学上显著的结论。论文中的排名仅供参考。
*   **LLM评判的可靠性风险**： 大量任务依赖LLM裁判，但其偏差（如自我增强效应）未被校准和报告，缺乏与人类专家评判的对齐验证，存在系统性的评分偏差风险。
*   **可复现性与开放性受限**： 为防泄漏和数据污染，官方完整提示词、任务资产、评分代码均**不公开**。这虽然有其理由，但极大限制了第三方对其实验的独立验证和审计，社区只能信任报告的数据。
*   **设计尚未经验校准**： 10D风险的权重和惩罚值是基于作者的主观设计选择，未通过实际业务损失等外部数据校准其严重程度。
