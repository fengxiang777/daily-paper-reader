## 摘要
选择具有不同成本-质量权衡的大语言模型（LLM）进行路由，已成为企业人工智能的一项基础部署特性。现有的路由器主要对每个LLM调用做出独立的路由决策。然而，智能体应用以长时间跨度的流程执行，其质量仅由延迟的任务级结果决定。这种不匹配使得按调用路由无法将反馈正确归因到单个路由决策。为缓解这一问题，我们提出TRACE-Router，一个任务级路由框架，使路由与监督单位保持一致。TRACE-Router在任务准入时使用上下文老虎机为每个任务分配一次模型，将所有后续LLM调用固定到所选后端，并利用任务的最终奖励更新其策略，同时考虑准确性和延迟。通过利用延迟的任务反馈，TRACE-Router学习适应工作负载的路由策略，同时避免显式的任务复杂度估计。在三个智能体基准测试中，TRACE-Router持续改善准确性-延迟权衡，达到非支配的帕累托前沿点。在tau2-Bench上，它比延迟匹配的单个模型插值高出7-8个准确点，而在Terminal-Bench上，它比最强的单模型基线高7.1个准确点，延迟低36%。

## Abstract
Routing to select large language models (LLMs) with different cost-quality trade-offs has become a fundamental deployment feature of enterprise AI. Existing routers, primarily make independent routing decisions for each LLM call. However, agentic applications execute as long-horizon workflows whose quality is determined only by a delayed, task-level outcome. This mismatch prevents per-call routers from correctly attributing feedback to individual routing decisions. Towards mitigating this, we present TRACE-Router, a task-level routing framework that aligns routing with the unit of supervision. TRACE-Router assigns each task to a model once at admission using a contextual bandit, pins all subsequent LLM calls to the selected backend, and updates its policy using the task's terminal reward, jointly accounting for accuracy and latency. By leveraging delayed task feedback, TRACE-Router learns routing policies that adapt to the workload while avoiding explicit task-complexity estimation. Across three agentic benchmarks, TRACE-Router consistently improves the accuracy-latency trade-off, achieving non-dominated Pareto frontier points. On tau2-Bench, it outperforms latency-matched interpolation between individual models by 7-8 accuracy points, while on Terminal-Bench it achieves 7.1 higher accuracy points than the strongest single model baseline with 36% lower latency.

### 1. 论文的核心问题与整体含义
- **核心问题**：现有LLM路由系统（如Request-level routers）对每个LLM调用做出独立决策，但在智能体（Agentic AI）工作流中，任务的成功或失败仅在长时间执行完成后才以单一结果（延迟任务级反馈）的形式呈现。这种**路由决策粒度**（逐调用）与**监督反馈粒度**（任务级）的错配，导致路由器无法正确将最终奖励归因到单个调用，从而限制了路由策略的学习与优化效果。
- **整体含义**：作者主张**路由的单位应与反馈的单位相匹配**。为了解决这一问题，需要设计一种在**任务级别**进行模型选择，并利用任务最终结果进行在线学习的路由框架，从而在保持端到端延迟合理的前提下，最大化任务完成的准确率。

### 2. 方法论
- **核心思想**：提出**TRACE-Router**框架，将模型路由从“单次调用选择”转变为**任务一致的自适应在线模型选择**。在任务开始时一次性选择后端，并在整个任务执行的生命周期内“固定”使用该模型，最后根据任务的终端奖励来更新路由策略。
- **关键技术细节**：
    - **任务一致路由**：为每个任务维护一个持久的`task_id`，当首个请求到达时通过路由策略选定一个后端模型`m`，存储`task_id`到`m`的映射（活动任务表`A`）。后续所有属于该任务的请求，都直接重用该映射，不进行重新路由，从而避免模型切换带来的状态失效和信用分配碎片化。
    - **上下文条件化的模型选择**：使用一个基于正则表达式的上下文分类器`g`，将任务依据初始描述（如关键词和长度）预先分到`EASY`, `MEDIUM`, `HARD`三个离散的上下文（`C`）之一。为每个上下文维护一个独立的**上下文老虎机（Contextual Bandit）**，以学习该难度类别下最优的模型选择策略。
    - **在线策略学习（冷启动UCB）**：默认采用冷启动上下文UCB（Upper Confidence Bound）策略。初始化阶段对每个上下文中的每个候选模型执行若干轮次强制探索（Round-robin），之后根据历史累积奖励和置信上界进行模型选择，选择规则为：
        $$m_t = \argmax_{m} \left( \hat{\mu}_{c_t,m} + \sqrt{\frac{2 \log(1/\delta)}{N_{c_t,m}}} \right)$$
        其中`\hat{\mu}`为平均奖励，`N`为拉取次数，`\delta`控制探索强度。
    - **任务级准确率-延迟联合奖励**：在任务终止后，将标准化后的准确率`a_{t,m}`（0至1）和剪裁后的延迟`\tilde{\ell}_{t,m}`（以预设`\ell_0`归一化至[0,1]），通过偏好参数`\alpha \in [0,1]`整合为联合奖励：
        $$r^{(\alpha)}_{t,m} = (1-\alpha) a_{t,m} - \alpha \tilde{\ell}_{t,m}$$
        偏好值`\alpha`决定了在准确率和延迟间的权衡（`\alpha=0`追求纯准确率，`\alpha=1`追求纯低延迟）。
    - **延迟信用分配**：任务完成时获得的联合奖励，仅用于更新该任务最初选定的上下文所对应的那个老虎机（即`B_{c_t}`）中相应模型的拉取次数和累计奖励统计。

### 3. 实验设计
- **场景与数据集**：实验覆盖了四个智能体基准，包括**tau2-Bench**（零售`retail`、电信`telecom`、航空`airline`领域）、**LiveCodeBench**和**Terminal-Bench**。
- **基准/对比方法**：
    - **单模型基线**：始终调用较小的后端（如Qwen3.5-4B）和较大的后端（如Qwen3.5-9B）。
    - **启发式路由器**：语义路由器（基于嵌入相似度）、复杂度路由器（使用与TRACE-Router相同的正则上下文分类器，但直接按固定规则将特定类别映射到特定模型）。
    - **消融变体（TRACE-Router的简化版）**：上下文无关变体（仅使用一个全局老虎机）；温启动（Warm-start）变体。
    - **任务级先知（Oracle）**：理论上限，分别为准确率先知（总是选择能解决该任务的模型）和延迟先知（总是选择能最快解决任务的模型）。
- **评估指标**：**任务准确率（Accuracy）** 与**平均延迟（Latency）**形成的帕累托前沿，并比较在给定延迟下的准确率优势。

### 6. 论文的主要结论与发现
- **帕累托前沿的主导地位**：TRACE-Router在多个基准上持续占据准确率-延迟的经验帕累托前沿（Pareto Frontier）的内部空间，其性能非支配其他所有基线，包括在两个τ2-Bench领域的联合图中完全支配复杂度路由器和语义路由器。
- **超越简单混合**：TRACE-Router在τ2-Bench上的表现，相比延迟匹配的单个模型随机混合（线性插值），准确率**高出7到8个点**，证明了其学习的是任务选择性的路由策略，而非概率混合。
- **实现“既快又准”**：在Terminal-Bench上，当两个后端模型解决的任务子集差异显著时，TRACE-Router以**低36%的延迟**，实现了比最强的大模型**高7.1个点**的准确率，甚至超越了“总是使用最快模型”的强度。
- **设计选择的有效性验证**：上下文条件化对前沿点的质量至关重要；**冷启动策略优于温启动**（因为温启动会过度固守先验，抑制发现后端模型互补性的探索）；在Bandit策略对比中，**UCB因其在不同基准上的稳定性**而胜出，尽管其他策略（如汤普森采样）在最佳参数下峰值性能相近。

### 7. 优点
- **新颖且务实的范式转换**：首次将智能体路由的粒度从请求提升到任务级别，解决了反馈对齐这一根本性问题，无需复杂的执行轨迹建模。
- **轻量级且无训练成本**：无需离线标注数据或训练分类器，采用在线Bandit算法从流式任务结果中实时学习，部署成本低，能自然适应工作负载和模型池的变化。
- **系统兼容性好**：通过一个简单的“粘性”任务-模型绑定即可实现，对现有智能体运行时和推理服务堆栈侵入性小，仅需一个持久化的`task_id`。
- **实验论证严谨**：使用了科学的基准（如以“延迟匹配插值”为对照），并系统性地通过消融实验揭示了上下文、初始化策略、探索策略等关键设计要素的影响，论据充分有力。

### 8. 不足与局限
- **上下文信号的表达力有限**：采用的基于正则表达式的难度分类器较为简单，其性能可能受益于任务本身特性的明显差异。面对模糊或高度复杂的任务时，这种基于规则的上下文划分可能无法最优地区分模型偏好。
- **单一模型绑定的僵化性**：任务与模型“硬绑定”后，无法在执行中途动态“升级”或“降级”。对于那些可能在执行中途变得简单（可转用快模型）或变得困难（需用强模型）的任务，该方法丧失了灵活调整的机会。
- **奖励函数的敏感性**：联合奖励依赖于`\ell_0`（用于延迟归一化的阈值）和偏好参数`\alpha`的人为先验设定。不恰当的值可能导致奖励信号失真或无法反映真实的部署偏好，需要一定的工程调参。
- **评估基线的局限性**：仅与同为“任务级路由”但采用固定规则的复杂度路由器和通用的语义路由器对比，未与更复杂的基于轨迹中间信号的路由方法（如SWE-Router）进行直接对比。
- **未建模并发和成本**：实验假设任务按流式进入并更新Bandit，但未明确分析在高并发下模型服务容量瓶颈、排队延迟或实际的API货币成本等因素与路由决策的相互影响。
