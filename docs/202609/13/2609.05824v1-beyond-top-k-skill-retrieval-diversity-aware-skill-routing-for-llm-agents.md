## 摘要
大型语言模型（LLM）智能体越来越依赖外部技能，但在大型技能注册库中为用户请求进行路由十分困难，因为许多技能在功能上冗余，而复杂任务往往需要互补的技能集。现有技能路由器通常仅根据查询相关性独立地对候选技能进行排序，这可能在冗余技能上浪费上下文预算。我们提出了一种多样性感知的重排序框架——多样性技能路由（DSR），该框架利用行列式点过程来平衡相关性与非冗余性。DSR 引入了一种查询残差多样性核函数，该核函数惩罚冗余的技能重叠，同时减少仅由共享查询相关性引起的惩罚。在 SkillRouter 基准测试上，与强大的逐点重排序基线相比，DSR 在召回率和完全覆盖率上均有提升，并且在多技能查询上的增益更大。这些结果表明，技能路由不仅应被视为相关性排序，而且应被视为互补集合选择。

## Abstract
Large language model (LLM) agents increasingly rely on external skills, but routing user requests over large skill registries is difficult because many skills are functionally redundant while complex tasks often require complementary skill sets. Existing skill routers typically rank candidates independently by query relevance, which can waste context budget on redundant skills. We propose Diverse Skill Routing (DSR), a diversity-aware reranking framework that uses a Determinantal Point Process to balance relevance and non-redundancy. DSR introduces a query-residual diversity kernel that penalizes redundant skill overlap while reducing penalties caused only by shared query relevance. On the SkillRouter benchmark, DSR improves recall and full coverage over a strong pointwise reranking baseline, with larger gains on multi-skill queries. These results suggest that skill routing should be treated not only as relevance ranking, but also as complementary set selection.

## 1. 论文的核心问题与整体含义

- **研究背景**：LLM 智能体越来越多地依赖外部技能库来获得超出文本生成的能力，例如调用 API、加载程序化知识模块等。
- **核心问题**：当技能注册库规模很大（如数万个技能）时，如何为给定用户请求选择一组合适的技能？现有技能路由器通常把该问题建模为逐点检索/重排序：独立地对每个候选技能与查询的相关性打分，然后取 top-k。
- **主要缺陷**：
  - 大型技能库中存在大量功能冗余的技能，逐点排序容易把多个高度重叠的技能同时排到前面，浪费有限的上下文窗口。
  - 许多真实智能体任务是组合式的，需要多个互补技能协同完成（如文档解析、信息抽取、数据转换、可视化），但独立排序无法保证覆盖面，可能遗漏必需的技能。
- **整体含义**：技能路由不应只是相关性排序，而应被视为“互补集合选择”问题，需要在相关性与非冗余性之间取得平衡。

## 2. 论文提出的方法论

- **总体框架**：提出 **Diverse Skill Routing (DSR)**，一种多样性感知的重排序框架。其沿用“检索-重排序”流程：先用检索器产生候选集，再用质量模型给每个候选打分，最后用行列式点过程（DPP）选择一组平衡相关性与非冗余性的技能。
- **关键技术细节**：
  - **候选检索**：使用编码器检索器（SR-Emb-0.6B）对查询和技能分别嵌入，利用余弦相似度检索 top-M 个候选，M 远小于总技能数（实验取 M=50）。
  - **质量分数**：使用逐点重排序模型（SR-Rank-0.6B）输出相关性 logit，通过 sigmoid 转换为非负质量分数 \(q_i(x)=\sigma(h_i(x))\)。
  - **DPP 选择**：在候选集上构造 DPP 核矩阵 \(L(x)_{ij}=q_i(x)\,\phi_x(s_i,s_j)\,q_j(x)\)，其中 \(\phi_x(s_i,s_j)\) 是查询条件技能相似度。DPP 分数为子集对应主子矩阵的行列式，通过最大化行列式选择子集。当 \(k=1\) 时退化为普通相关性排序。
  - **查询残差多样性核**：为避免把所有相似性都当作冗余，先从技能嵌入中移除与查询对齐的分量：
    \[
    r_i = e_i - (e_i^\top e_x)e_x
    \]
    再将残差与原嵌入按系数 \(\lambda\) 混合并归一化：
    \[
    \tilde{z}_i = \lambda r_i + (1-\lambda)e_i,\quad z_i=\tilde{z}_i/\|\tilde{z}_i\|_2
    \]
    相似度定义为 \(\phi_x(s_i,s_j)=(1+z_i^\top z_j)/2\)。这样多样性惩罚聚焦于查询正交方向上的重叠，减少因共同相关性造成的误伤。
  - **贪心 MAP 选择**：使用增量 Cholesky 更新，每次选择使对数行列式边际增益最大的候选，直到选出 k 个；最终按质量分数排序输出。
- **算法流程**：先嵌入查询与技能 → 检索候选集 → 计算质量分数 → 计算查询残差表示 → 构造 DPP 核 → 贪心选择 → 按质量排序返回。

## 6. 论文的主要结论与发现

- DSR 在不改变底层检索和重排序模型的情况下，通过多样性感知选择提升了技能集合的覆盖能力。
- 在 SkillRouter 上，DSR 相比逐点重排序基线提高了 Recall 和 Full Coverage；@50 时提升更明显（如全部查询 Recall 从 0.754 到 0.808，Full Coverage 从 0.560 到 0.633）。
- **多技能查询收益更大**：多技能子集上 Full Coverage@50 从 0.458 提升到 0.551，说明多样性选择主要改善组合式任务。
- 消融显示：**查询残差核是关键**。用标准余弦核会大幅降低多技能 Full Coverage（如 @10 从 0.441 降到 0.254），说明简单惩罚所有相似性会误删有用的互补技能。
- 质量分数仍然重要：用重排序器质量优于只用嵌入相似度；但仅有强相关性模型而不做多样性也不够。
- 单技能查询上，强逐点相关性信号通常已足够，DSR 与基线持平，进一步说明多样性收益主要集中在多技能场景。

## 7. 优点

- **问题定位清晰**：将技能路由从独立排序重新定义为互补集合选择，贴合真实多步任务需求。
- **方法简洁且可插拔**：DSR 只替换最终选择层，不改动检索器和重排序器，易于集成到现有流水线。
- **查询残差核设计有新意**：有效区分“因任务相同而相似”和“功能冗余而相似”两种情况，避免过度惩罚有用的互补技能。
- **实验控制严格**：保持检索器和重排序器一致，能隔离多样性选择本身的贡献；消融实验明确验证了核函数和质量信号的作用。
- **多技能场景下的实证支持充分**：在多技能子集和更大截断点上的提升一致，验证了核心假设。

## 8. 不足与局限

- **评估规模有限**：仅 75 个专家验证查询，领域和任务类型覆盖面有限，后续需在更多样化、更复杂的 benchmark 上验证。
- **指标与真实任务成功存在差距**：只评估 Recall/Full Coverage，未直接测量下游智能体执行成功率；即使所有目标技能被检索到，智能体仍可能因规划、工具使用等原因失败。
- **依赖候选检索**：DPP 选择只能在已检索到的候选集内进行，如果初始检索阶段遗漏了必要技能，DSR 无法恢复；论文也承认这一点。
