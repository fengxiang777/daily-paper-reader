## 摘要
尽管大语言模型（LLMs）已展现出令人瞩目的能力，但由于固定的上下文长度限制，它们在处理极长上下文时往往表现不佳。为解决这一问题，MemAgent 等顺序方法通过分段读取文本并迭代更新固定大小的记忆来扩展有效上下文。然而，这种顺序范式存在高延迟问题，且需要昂贵的强化学习（RL）训练，这可能导致在特定数据集上过拟合。为克服这些局限，我们提出 ConvMem，一个无需训练、高度可并行化的框架，将长上下文推理重构为层次化卷积。受 CNN 启发，ConvMem 将带有特定查询提示的 LLM 视为卷积核。该核以层次化方式总结文本段，将推理路径从线性链缩短为对数树。具体而言，ConvMem 融合了可配置步长和跳跃连接，以确保稳健的证据捕获与传播，同时采用多核卷积将复杂查询分解为解耦的语义通道。这一设计不仅减轻了错误累积，还支持在文本段和推理线程两个维度上进行大规模并行化。在 RULER-HotpotQA 和 RULER-2WikiMultiHopQA 上的实验表明，ConvMem 优于免训练基线，并避免了 RL 训练模型在分布外任务中常见的对参数化先验过拟合的风险。

## Abstract
While Large Language Models (LLMs) have demonstrated impressive capabilities, they often struggle with extremely long contexts due to fixed context limits. To address this, sequential approaches like MemAgent extend the effective context by reading text in segments and iteratively updating a fixed-size memory. However, this sequential paradigm suffers from high latency and requires costly reinforcement learning (RL) training, which can lead to overfitting on specific datasets. To overcome these limitations, we propose ConvMem, a training-free, highly parallelizable framework that reformulates long-context reasoning as a hierarchical convolution. Inspired by CNNs, ConvMem treats an LLM prompted with a specific query as a convolutional kernel. This kernel summarizes text segments hierarchically, shortening the reasoning path from a linear chain into a logarithmic tree. Specifically, ConvMem integrates \textit{Configurable Strides} and \textit{Skip Connections} to ensure robust evidence capture and propagation, while employing \textit{Multi-Kernel Convolution} to decompose complex queries into disentangled semantic channels. This design not only mitigates error accumulation but also enables massive parallelization across both text segments and reasoning threads. Experiments on RULER-HotpotQA and RULER-2WikiMultiHopQA demonstrate that ConvMem outperforms training-free baselines and avoids the risk of overfitting to parametric priors often observed in RL-trained models on out-of-distribution tasks.

## 2. 论文提出的方法论

### 2.1 核心思想

- 将**冻结的 LLM 作为语义卷积核**，通过提示词驱动，对文本段进行非线性“文本到文本”的提取与压缩。
- 类比 CNN 的空间卷积，ConvMem 用多个并行核在文本上滑动，逐层汇总，形成层次化树状结构。
- 形式化符号：\(W\)（核大小/窗口大小）、\(S\)（步长）、\(L\)（层数）、\(C\)（通道数/子问题数）。

### 2.2 语义卷积核

- 定义核函数 \(K_{LLM}(x, q; p)\)，输入为局部文本段 \(x\) 和查询 \(q\)，输出为摘要 \(h\) 和相关性分数 \(r\)。
- 相关性分数 \(r \in \{0, 1, 2\}\)：
  - \(r=0\)：无关；
  - \(r=1\)：可能相关；
  - \(r=2\)：关键（包含直接证据或答案）。
- 对整个文档的卷积操作：
  \[
  H, R = \text{Conv}(D, K) = \left( \bigoplus_{i=1}^{M} h_i, \{r_i\}_{i=1}^{M} \right)
  \]
  即对所有段并行应用核，得到摘要序列 \(H\) 和相关性分数序列 \(R\)。

### 2.3 三个关键机制

- **可配置步长（Configurable Strides）**：
  - 采用重叠滑动窗口（\(S < W\)），消除文本分段边界截断导致的语义断裂。
  - 每个 token 被扫描 \(W/S\) 次（过扫描因子），实现多视角交叉验证，提升证据召回与稳健性。
- **跳跃连接（Skip Connections）**：
  - 受残差网络启发，当某段在输入层被标记为关键（\(r=2\)）时，该原始段直接加入残差缓冲 \(B\)，绕过中间压缩层，传播到最终推理阶段。
  - 保留细粒度信息（如精确日期、实体名），防止层次摘要丢失关键细节。
- **多核卷积（Multi-Kernel Convolution）**：
  - 将复杂查询 \(Q\) 分解为 \(C\) 个正交子问题 \(\{q^{(1)}, \dots, q^{(C)}\}\)。
  - 每个子问题初始化一个独立核 \(K^{(c)}\)，在同一文档上并行提取相关语义，生成独立通道 \(H^{(c)}\)。
  - 防止多个逻辑线索相互干扰，实现语义解耦。

### 2.4 层次化并行推理工作流

- **Layer 0（输入处理）**：将原始文档 \(D\) 切分为 \(M_0\) 个重叠段，每个通道的核并行扫描，生成初始摘要并更新残差缓冲 \(B^{(c)}\)。
- **Layer l（递归总结）**：将上一层的摘要序列拼接，重新切分为新段，递归应用卷积：
  \[
  H^{(l,c)} = \text{Conv}(H^{(l-1,c)}, K^{(c)})
  \]
  摘要长度按压缩因子 \(\alpha\) 指数衰减：\(N_l \approx N_0 \cdot \alpha^l\)，有效感受野指数扩大。
- **最终聚合**：
  - 每个通道独立生成子答案 \(a^{(c)}\)，结合高层摘要 \(H^{(L,c)}\) 和残差缓冲 \(B^{(c)}\)。
  - 再将原查询 \(Q\) 与所有子问题-子答案对聚合，生成最终答案 \(A\)。
- **并行性**：层内所有段和所有通道相互独立，理论上推理延迟只取决于树深度：
  \[
  T_{\text{latency}} \propto O(\log N)
  \]
  相比顺序方法的 \(O(N)\)，可处理百万 token 上下文。

## 6. 论文的主要结论与发现

- **性能**：ConvMem 在训练免费方法中达到 SOTA，在 RULER-HotpotQA 和 RULER-2WikiMultiHopQA 上显著优于原版 Qwen2.5-32B 和所有免训练基线。
- **泛化性**：在 OOD 数据集上，RL 训练的 MemAgent 性能明显下降（从 75 F1 掉到 60 左右），而 ConvMem 保持相对稳定（约 59–72 F1），显示其更依赖上下文推理而非参数记忆。
- **机制有效性**：
  - 过扫描因子为 5 时最佳，单次扫描因边界截断导致性能下降；
  - 跳跃连接对精确实体检索至关重要，移除后 Sub-EM 从 77.3 降至 65.6；
  - 多核卷积显著提升多跳任务准确率（68.0 → 77.3）；
  - 核大小 \(W=8000\) 最优。
- **模型无关性**：ConvMem 应用于 7B、32B、72B 骨干均带来一致提升，无需适配。
- **RL 过拟合风险**：案例分析显示 RL 模型会输出与上下文矛盾的记忆标签（如“Levni Yilmaz”），而 ConvMem 忠实提取上下文中的“Lev Yilmaz”。

## 7. 优点

- **免训练**：无需 RL 或微调，降低训练成本，避免过拟合特定数据集，提高分布外泛化能力。
- **高并行性**：将顺序 \(O(N)\) 依赖转化为对数深度 \(O(\log N)\)，理论延迟极低，支持百万 token 推理。
- **架构创新**：借鉴 CNN 的卷积、步长、跳跃连接、多通道思想，为长上下文推理提供了新的结构化视角。
- **机制清晰**：可配置步长、跳跃连接、多核卷积三个组件可独立消融，效果可解释。
- **模型无关**：可即插即用于不同规模 LLM，无需额外适配。
- **实验对比全面**：涵盖标准 LLM、免训练记忆、RL 专家三类方法，并构建 OOD 数据集验证泛化。

## 8. 不足与局限

- **总计算成本较高**：虽然延迟低，但并行多通道和多层扫描导致总 token 消耗高于线性扫描方法，推理算力需求大。
- **依赖查询分解质量**：多核卷积依赖于骨干模型正确分解复杂查询为子问题；若分解不合理，后续通道可能基于不完整前提失效。
- **数据集覆盖有限**：仅评估了 RULER-HotpotQA 和自建的 RULER-2WikiMultiHopQA，未在更多类型的长上下文任务（如长文档摘要、代码库理解）上验证。
- **对比公平性存疑**：Mem-α 在本实验框架下 F1 极低，可能与实现或生成方式有关，未深入分析原因，可能影响该类方法的公平比较。
- **指标局限性**：EM 对长生成过严，Sub-EM 和 ACC_L 虽缓解但仍有歧义；论文通过案例承认数据标签存在拼写错误等质量问题。
- **资源细节缺失**：未报告 GPU 数量、推理吞吐量或端到端延迟的实际测量，难以评估实际部署效率。
- **超参敏感性**：最佳核大小、步长等需要针对任务调节，可能增加实际使用中的调参成本。
