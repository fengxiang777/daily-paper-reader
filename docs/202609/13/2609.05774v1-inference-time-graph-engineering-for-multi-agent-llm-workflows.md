## 摘要
近期的多智能体LLM系统越来越依赖图结构通信来协调专业化智能体。我们从图工程的角度重新审视多智能体编排：不是优化静态拓扑，而是合成一个任务条件的时序工作流图，该图同时指定智能体连接关系和边级通信语义。我们提出 ReActNet，一个无需训练的框架，它将查询和一组角色专用智能体编译为一系列有向通信图。每个图快照对应一个推理阶段，每条边携带一条自然语言指令，指定源智能体应向目标智能体提供的消息。编译后的时序图随后通过结构化消息传递执行：智能体将其先前状态与来自控制器分配邻居的消息进行整合以更新其推理状态，最后聚合器将结果状态合成为答案。这种设计将图编译与图执行分离，使多智能体协调显式、可检查且任务条件化，无需强化学习或基于梯度的拓扑优化。在知识推理、数学问题求解、代码生成和 GAIA 风格助手任务中，ReActNet 相较于固定拓扑和学习拓扑基线均取得一致改进，同时保持有竞争力的推理成本。这些结果表明，有效的多智能体编排不仅取决于哪些智能体进行通信，还取决于设计可执行的工作流图，以编码推理过程中信息应在何时、为何以及如何流动。

## Abstract
Recent multi-agent LLM systems increasingly rely on graph-structured communication to coordinate specialized agents. We revisit multi-agent orchestration from a graph-engineering perspective: rather than optimizing a static topology, we synthesize a task-conditioned temporal workflow graph that jointly specifies agent connectivity and edge-level communication semantics. We introduce ReActNet, a training-free framework that compiles a query and a set of role-specialized agents into a sequence of directed communication graphs. Each graph snapshot corresponds to one reasoning stage, and each edge carries a natural-language instruction specifying the message that a source agent should provide to a target agent. The compiled temporal graph is then executed through structured message passing: agents update their reasoning states by integrating their previous states with messages from controller-assigned neighbors, and a final aggregator synthesizes the resulting states into the answer. This design separates graph compilation from graph execution, making multi-agent coordination explicit, inspectable, and task-conditioned without requiring reinforcement learning or gradient-based topology optimization. Across knowledge reasoning, mathematical problem solving, code generation, and GAIA-style assistant tasks, ReActNet consistently improves over fixed-topology and learned-topology baselines while maintaining competitive inference cost. These results suggest that effective multi-agent orchestration depends not only on which agents communicate, but also on engineering executable workflow graphs that encode when, why, and how information should flow during reasoning.

## 2. 方法论

### 2.1 核心思想

- 提出 **ReActNet**，一个**免训练**的“编译—执行”框架：
  - **编译阶段**：LLM 控制器把输入查询和一组角色专用智能体，一次性编译为**指令类型化的时序工作流图**。
  - **执行阶段**：角色专用智能体按照编译好的图进行**结构化消息传递**，更新自身推理状态，最后由聚合节点生成答案。
- 与拓扑学习方法不同，ReActNet 不训练图生成器，而是在推理时直接合成任务条件图；且每条边不仅表示允许通信，还携带自然语言指令，表征**为什么通信、应携带什么推理贡献**。

### 2.2 形式化定义

- 多智能体交互图：`G = {G^(t)}^T_{t=1}`，共有 `T` 个图快照；每个快照 `G^(t) = (V, E^(t))` 共享相同节点集 `V`（`|V|=N`），边集随时间变化。
- 每个节点 `v_i` 对应一个角色专用智能体 `A^{(i)}`。
- 有向边 `e^{(t)}_{j→i}` 表示第 `t` 轮智能体 `j` 向智能体 `i` 发送消息。
- 每条有向边携带一条**边指令** `ξ^{(t)}_{j→i}`，由控制器生成，指定源智能体应为目标智能体执行什么推理功能（如提出策略、检查计算、提供代码、寻找反例、验证一致性等）。

### 2.3 三阶段流程

1. **控制器编译图**：
   - 控制器 `F_controller` 接收控制器提示 `p^{controller}_{role}`、交互轮数 `T`、多智能体系统描述 `p_{MAS}` 和查询 `q`，一次性生成完整时序工作流图：
     `W_q = {G^{(t)}}^T_{t=1} = F_controller(p^{controller}_{role}; T; p_{MAS}; q)`
   - 每个快照 `G^{(t)} = (V, E^{(t)}, ξ^{(t)})` 包含固定节点集、时变有向边集和边指令集。
   - 多智能体系统描述通过拼接各角色提示构造：
     `p_{MAS} = "The system consists of N agents, and the role for each agent is: " ⊕ {p^{(i)}_{role}}^N_{i=1}`

2. **执行时序工作流图**：
   - **初始化**：每个智能体 `A^{(i)}` 独立生成初始推理状态：
     `r^{(i)}_0 = A^{(i)}(p^{(i)}_{role}; q)`
   - **逐轮消息传递**（`t = 1..T`）：
     - 对于每条有向边 `e^{(t)}_{j→i}`，源智能体根据边指令生成消息：
       `m^{(t)}_{j→i} = A^{(j)}(p^{(j)}_{role}; q; r^{(j)}_{t-1}; ξ^{(t)}_{j→i})`
     - 对于目标智能体 `A^{(i)}`，令入邻域 `N^{(t)}_i = {j | e^{(t)}_{j→i} ∈ E^{(t)}}`，聚合所有入消息 `m^{(t)}_i = {m^{(t)}_{j→i}}_{j∈N^{(t)}_i}`，然后更新状态：
       `r^{(i)}_t = A^{(i)}(p^{(i)}_{role}; q; r^{(i)}_{t-1}; m^{(t)}_i)`

3. **最终合成节点**：
   - 执行完 `T` 轮后，每个智能体有最终状态 `r^{(i)}_T`。
   - 聚合器 `F_syn`（LLM 实现）综合所有最终状态生成答案：
     `a = F_syn(p^{syn}_{role}; {r^{(i)}_T}^N_{i=1}; q)`
   - 合成节点负责识别共识、消解分歧并输出格式良好的最终响应。

### 2.4 关键特点

- **指令类型化边**：边 = `((j,i), ξ^{(t)}_{j→i})`，统一了图拓扑和通信语义，比邻接矩阵更具表达力。
- **一次性编译**：控制器在交互前一次性规划整个多轮协议，不进行在线重规划或迭代优化。
- **免训练**：无需强化学习、梯度优化或任务特定训练；控制器和聚合节点均通过提示工程实现。

## 6. 主要结论与发现

- ReActNet 在 6 个主数据集中的 5 个上取得最佳性能，平均分（92.75）显著高于所有基线；在 GSM8K 上排名第三但差距很小。
- 在 HumanEval 上提升尤其明显（21.06 个百分点相对 Vanilla），在 AQuA 上提升 17.36 个百分点。
- **效率**：ReActNet 免训练，无训练 token 成本；在 GSM8K 上推理时间（1.7h）和推理 token（5.9M）低于或接近高表现基线，总 token 消耗显著低于需要优化训练的方法。
- **可扩展性**：在 MMLU 上，随着智能体数量从 5 增至 20，ReActNet 推理时间几乎不变（约 7 分钟），准确率保持有竞争力（79.74 → 77.77）。
- **GAIA 任务**：ReActNet 取得最佳准确率（12.72），优于 G-Designer（10.91）。
- **参数敏感性**：`T=3` 是最优轮数；`T=1` 已超过 G-Designer，但 `T=5` 反而下降（冗余或冲突消息）。
- **图演化模式**：定性分析显示 ReActNet 生成**相位感知时序图**：早期轮侧重问题分解和信息收集，中期侧重计算和交叉验证，后期侧重一致性检查和答案合成；边密度和方向随任务动态变化，形成反馈回路。
- **核心结论**：有效的多智能体性能不仅取决于“哪些智能体通信”，更取决于工程化可执行工作流图，显式编码信息流动的**时机、原因和方式**。

## 7. 优点

- **新颖的图工程视角**：将多智能体编排从拓扑优化提升为“拓扑 + 边级语义 + 时序阶段”的联合设计，形式化清晰。
- **免训练、推理时合成**：无需强化学习、梯度优化或任务特定训练，实际部署门槛低，对未见任务适应性强。
- **指令类型化边**：边携带自然语言指令，统一了结构和语义，使工作流图更具表达力和可解释性。
- **编译与执行分离**：控制器一次性生成全局连贯的多轮协议，执行过程显式可追踪（谁在何时向谁发送了什么指令）。
- **实验设计扎实**：覆盖多类任务、多种基线，并包含效率、扩展性、参数敏感性和不同 LLM 骨干的补充实验。
- **定性分析丰富**：附录展示 GAIA 样例的图快照，帮助理解时序图的实际演化，增强可解释性。
