## 摘要
自演化的运行时执行框架（runtime harness）可以显著提升大语言模型（LLM）智能体的能力，并为优化智能体执行提供一种有前景的范式。现有框架演化方法通常依赖迭代搜索，根据任务实例的执行反馈反复评估和修改候选框架。尽管这种范式能够持续优化框架，但由于反复执行智能体和修改代码，会带来大量时间开销，并且可能对已观测任务和特定失败模式过拟合，导致对未见任务的泛化能力下降。我们发现，缺乏有原则的失败诊断是框架演化的关键瓶颈：一次观测到的失败可能反映模型特有的缺陷，也可能反映系统性的框架缺陷，而直接针对个别失败进行优化可能导致不必要的模型特有适配。因此，我们提出 Ecdysis，一个高效且有效的框架，它区分模型特有适配与框架级修复，并通过识别跨任务中反复出现的失败模式，使适配偏向系统性的框架缺陷。Ecdysis 采用批量级跨实例失败聚合范式，联合分析来自多个任务实例的失败证据，并进一步引入失败驱动的协作精化来诊断失败原因并迭代精化框架修改规范。通过结合跨实例失败分析与多角色诊断，Ecdysis 以更低的训练时间实现更有效的框架演化。实验表明，与现有框架演化方法相比，Ecdysis 在框架训练上实现了最高 1.84 倍的加速，同时将所得框架的推理准确率提高了 18.56%。

## Abstract
Self-evolving runtime harnesses can substantially improve the capabilities of large language model (LLM) agents and provide a promising paradigm for optimizing agent execution. Existing harness evolution methods typically rely on iterative search, repeatedly evaluating and revising candidate harnesses based on execution feedback from task instances. While this paradigm enables continuous harness optimization, it incurs substantial time overhead due to repeated agent executions and code modifications, and may overfit to observed tasks and specific failure patterns, resulting in degraded generalization to unseen tasks. We identify the lack of principled failure diagnosis as a key bottleneck in harness evolution: an observed failure can reflect either model-specific deficiencies or systematic harness deficiencies, and directly optimizing against individual failures can lead to unnecessary model-specific accommodation. We therefore propose Ecdysis, an efficient and effective framework that distinguishes model-specific accommodation from harness-level repair and biases adaptation toward systematic harness deficiencies by identifying recurring cross-task failure patterns. Ecdysis adopts a batch-level cross-instance failure aggregation paradigm to jointly analyze failure evidence from multiple task instances and further introduces Failure-Driven Collaborative Refinement to diagnose failure causes and iteratively refine harness modification specifications. By combining cross-instance failure analysis with multi-role diagnosis, Ecdysis enables more effective harness evolution with lower training time. Experiments show that Ecdysis achieves up to a 1.84x speedup in harness training compared with existing harness evolution methods, while improving the reasoning accuracy of the resulting harnesses by 18.56%.

## 2. 论文提出的方法论

### 核心思想

- Ecdysis 将失败视为诊断信号，而不是直接修改指令。
- 通过**批量级跨实例失败聚合**，联合分析来自多个任务实例的失败证据，识别反复出现的跨任务失败模式，从而优先处理更可能是系统性 harness 缺陷的问题。
- 引入**失败驱动的协作精化（Failure-Driven Collaborative Refinement, FDCR）**，由多角色从互补视角诊断失败原因并迭代精化修改规范，减少失败解释的歧义。

### 关键技术细节

- **批量级失败聚合**：
  - 执行训练任务并收集轨迹 \(T_i\)。
  - 用评估框架得到分数 \(S(\tau)\)，定义失败信号 \(f_\lambda(\tau)=\mathbb{I}[S(\tau)<\lambda]\)。
  - 将失败轨迹转换为结构化记录（任务 ID、失败决策、终止原因、工具调用历史等），形成失败证据集 \(B_i\)。
  - 将失败记录分组 \(G_i\)，**优先保留覆盖至少两个不同任务的失败组**，因为单任务重复失败不足以说明机制具有跨任务泛化性。
  - 失败组是诊断证据而非强制修复目标，候选 harness 不必解决所有失败组。
  - **减少编码代理调用**：设一轮失败记录数为 \(n_i\)，串行处理需要 \(n_i\) 次调用，而 Ecdysis 每轮只调用一次编码代理，因此总编码代理调用数 \(N_{\text{round}}=\sum_i\mathbb{I}(n_i>0)\le\sum_i n_i=N_{\text{serial}}\)。

- **失败驱动的协作精化（FDCR）**：
  - 角色包括 **Analyst**（分析师）、**Critic**（批评者）、**Engineer**（工程师）和 **Moderator**（主持人）。
  - Analyst 识别潜在 harness 缺陷并提出最小、有针对性的更新；Critic 评估提案是否匹配失败证据，检查触发条件过宽、合法行为被阻断、运行时契约违反、回归等风险；Engineer 跟踪共识与未解决分歧，识别需要进一步澄清的问题。
  - 多角色顺序执行，共享转录，每个角色能看到之前的讨论。
  - 经过固定轮数精化后，Moderator 综合失败证据与完整转录，产出**结构化修改规范**。
  - 该规范不直接修改 harness，而是交给编码代理（coding agent）执行实际代码修改，实现诊断与实现解耦。

- **候选接受标准**：
  - 设 \(J_{\text{train}}(H)\) 为训练集总分，当且仅当 \(J_{\text{train}}(H^c_i)>J_{\text{train}}(H_{i-1})\) 时接受候选，否则保留旧 harness。
  - 只要求整体训练集分数提升，不强制每个任务都改进。

- **模型适应比例分解**：
  - 将聚合更新分解为 \(\Delta H = t\,\Delta H_{\text{model}} + (1-t)\,\Delta H_{\text{harness}}\)，其中 \(t\) 为模型特定适配决策占比。
  - Ecdysis 的目标是减小 \(t\)，即减少不必要的模型特定适配，从而保持更通用的有效动作空间。

### 算法流程概要

1. 初始化 harness \(H_0 \leftarrow H_{\text{base}}\)。
2. 每一轮 \(i\)：
   - 用当前 harness \(H_{i-1}\) 执行训练任务，收集轨迹。
   - 根据分数阈值聚合失败证据。
   - 若失败证据非空，分组并运行 FDCR 生成修改规范。
   - 编码代理根据规范修改 harness 得到候选 \(H^c_i\)。
   - 在训练集上验证候选，严格改进则接受，否则保留旧 harness。
3. 冻结最终 harness \(H_F = H_R\)。
